# Internationalization

English UI copy is authored beside each semantic key at the call site. Run the
commands in this guide from `web/`. `pnpm i18n:extract` syncs those defaults
directly into `src/i18n/locales/en/translation.ts`; that checked-in catalog
defines the TypeScript resource contract in `src/i18n/i18next.d.ts`. Every other
UI catalog has the same canonical keys.

## Adding copy

React components keep `useTranslation()` and include the stable key plus English default at the
call site:

```tsx
t("calendar.status.completed", "Done");
t("home.hi", "Hi {{name}}", { name });
t("common.workoutCount", "{{count}} workout", { count });
```

Non-React modules use `translate(key, defaultValue, values)` from
`src/i18n/translate.ts`. React UI
registries such as weekday, muscle, equipment, and progression labels live in feature hooks with
literal `t(key, defaultValue)` calls. This keeps language changes reactive and makes every key and
English default directly visible to the official extractor; there is no English-value reverse
lookup.

Use named interpolation variables. Plurals use i18next JSON v4 suffixes, a numeric `count`, the
locale categories returned by `Intl.PluralRules`, and an explicit `_zero` form. Do not add an
uncounted base resource or manually branch English singular/plural copy.

Pass `Date` objects to the catalog's `{{date, datetime}}` value. `formatDate` and `fmtDate` preserve
the product's compact date styles while delegating locale-aware output to i18next's built-in
`Intl.DateTimeFormat` formatter; do not format dates into strings before they reach that boundary.

## Extracting and checking

Run:

```sh
pnpm i18n:extract
pnpm i18n:check
```

The extractor uses `--sync-primary`, updates
`src/i18n/locales/<language>/translation.ts` directly, and
preserves existing secondary-language copy. Empty secondary entries fall back through English.
`removeUnusedKeys` is disabled because exercise instructions share the locale tree but are
generated separately. Exercise instructions are authored in
`catalog/instructions/<language>.ts` (English in `catalog/exercises.ts`) and
generated into JSON shards under `public/instructions`. They are loaded on demand by the exercise-detail flow and are not
extractor-owned.
