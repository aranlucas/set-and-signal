# Internationalization

English UI copy is authored beside each semantic key at the call site. `pnpm i18n:extract` syncs
those defaults directly into `src/locales/en/translation.ts`; that checked-in catalog defines the
TypeScript resource contract in `src/i18next.d.ts`. Every other UI catalog has the same canonical
keys.

## Adding copy

React components keep `useTranslation()` and include the stable key plus English default at the
call site:

```tsx
t("calendar.status.completed", "Done");
t("home.hi", "Hi {{name}}", { name });
t("common.workoutCount", "{{count}} workout", { count });
```

Non-React modules use `translate(key, defaultValue, values)` from `src/lib/translate.ts`. React UI
registries such as weekday, muscle, equipment, and progression labels live in feature hooks with
literal `t(key, defaultValue)` calls. This keeps language changes reactive and makes every key and
English default directly visible to the official extractor; there is no English-value reverse
lookup.

Use named interpolation variables. Plurals use i18next JSON v4 suffixes, a numeric `count`, the
locale categories returned by `Intl.PluralRules`, and an explicit `_zero` form. Do not add an
uncounted base resource or manually branch English singular/plural copy.

Pass `Date` objects to the catalog's `{{date, datetime}}` value. `formatDate` and `fmtDate` preserve
the product's compact date styles while delegating locale-aware output to i18next's built-in
`Intl.DateTimeFormat` formatter; do not format dates into strings before they reach that boundary.

## Extracting and checking

The official `i18next-cli` is pinned as a development dependency. Run:

```sh
pnpm i18n:extract
pnpm i18n:check
```

The extractor uses `--sync-primary`, updates `src/locales/<language>/translation.ts` directly, and
preserves existing secondary-language copy. Empty secondary entries fall back through English.
`removeUnusedKeys` is disabled because exercise instructions share the locale tree but are
generated separately. The catalog/source checks still reject translation-catalog parity drift and
compatibility adapters. Exercise instructions use sibling `src/locales/<language>/exercises.ts`
modules. They are ordinary namespaces handled by the same generic lazy loader and are not
extractor-owned. Only `translation` is loaded at startup; the exercise-detail screen requests
`exercises` on demand. More namespaces can be added with the same directory convention and no
loader special case.

`i18n:check` enforces catalog parity, no missing or extra canonical keys, named interpolation
parity, locale-specific plural categories, explicit zero forms, reserved-separator rules, semantic
source keys/defaults, lazy loading, supported-language activation, date locales, exercise-namespace
fallback, UI fallback behavior, and the React hook/imperative-module boundary.
